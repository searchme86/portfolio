프레임워크 없는 SPA 실험
Vanilla JS 어플리케이션 구현

"왜 React가 필요한가?" 질문에 답하기 위해 Vanilla JS로 SPA 수준의 복잡한 기능을 구현한 학습 프로젝트

  • 프로젝트 개요:

    React 학습 후 "과연 프레임워크 없이도 현대적 웹앱을 만들 수 있을까?"라는 호기심으로 시작했습니다. DOM 직접 조작, 컴포넌트 패턴, 상태 관리를 순수 JavaScript로 구현하며 프레임워크의 필요성을 체감했습니다.

  • 개발 동기:

    웹 개발 입문 단계에서 jQuery의 DOM 조작과 이벤트 처리 방식을 실무적으로 학습하고, 기존 웹사이트를 클론 코딩하며 실제 개발 프로세스를 경험하기 위한 프로젝트였습니다.

  • 핵심 목표:
    • 장바구니 시스템 - localStorage 기반 전역 상태 관리
    • Swiper 동기화 - 상품 삭제시 슬라이더 업데이트 이슈 해결
    • 스크롤 애니메이션 - IntersectionObserver 활용한 시각적 피드백
    • 반응형 4단계 - 360/760/861/1170px 브레이크포인트
    • 검색 & 필터링 - 실시간 상품 검색과 카테고리 필터

  • 이 프로젝트를 통해 컴포넌트 재사용의 어려움, 상태 변화 추적의 복잡성, DOM 조작의 성능 이슈, 타입 안전성 부재 등을 직접 경험하며 React Hook, 가상 DOM, TypeScript의 가치를 몸소 체감했습니다.

기술스택

이 프로젝트에서 사용된 주요 기술들과 그 선택 이유를 소개합니다.

Core Technologies

  • Vanilla JavaScript (ES6+)
  • HTML5 (시맨틱 마크업)
  • CSS3 & SCSS

Build Tools

  • Vite (빠른 개발 서버)
  • SCSS Preprocessor
  • ES Modules

External Libraries

  • Swiper.js (이미지 슬라이더)
  • IntersectionObserver API
  • Web APIs (localStorage, etc.)

개발 환경

  • GitHub Pages (배포)
  • Chrome DevTools
  • Cross-browser Testing

기술 선택 이유:

Vanilla JavaScript를 선택한 가장 큰 이유는 프레임워크의 필요성을 체감하기 위함이었습니다. Vite의 빠른 HMR과 빌드 최적화를 경험하고, ES 모듈 기반 개발 서버의 장점과 플러그인 생태계를 활용한 개발 워크플로우 개선에 집중했습니다.

구현사항

  • 프레임워크 없이 SPA 구현:

    1. 장바구니 시스템
    localStorage 기반 전역 상태 관리로 장바구니 기능을 구현했습니다. 상품 추가, 삭제, 수량 변경 시마다 상태를 동기화하고, 페이지 새로고침 후에도 데이터가 유지되도록 했습니다.

    2. Swiper 동기화
    상품 삭제 후 Swiper 슬라이더 동기화 문제를 해결했습니다. DOM 변경 후 Swiper 인스턴스를 업데이트하고, 현재 슬라이드 위치를 적절히 조정하는 로직을 구현했습니다.

    3. 스크롤 애니메이션
    IntersectionObserver를 활용해 요소가 뷰포트에 들어올 때 애니메이션을 실행하는 시스템을 구축했습니다. 성능을 고려한 lazy loading과 함께 부드러운 사용자 경험을 제공했습니다.

    4. 반응형 4단계 시스템
    360px/760px/861px/1170px 브레이크포인트로 구분된 반응형 레이아웃을 구현했습니다. 각 디바이스에 최적화된 UI/UX를 제공하며, 터치 인터페이스도 고려했습니다.

    5. 검색 & 필터링
    실시간 상품 검색과 카테고리 필터링 기능을 순수 JavaScript로 구현했습니다. 디바운싱을 적용해 성능을 최적화하고, 검색 결과에 따른 UI 업데이트를 담당했습니다.

    성과와 한계:
    완성된 프로젝트는 실제 쇼핑몰과 유사한 기능을 제공했지만, 코드 복잡성과 유지보수성 측면에서 프레임워크의 필요성을 절실히 느꼈습니다. 특히 상태 관리와 컴포넌트 재사용 부분에서 React의 장점을 깨닫게 되었습니다.

해결과제

  • 개발하며 깨달은 React의 필요성:

    1. 컴포넌트 재사용의 어려움
    동일한 UI 요소를 다른 곳에서 사용할 때마다 HTML을 복사하고 JavaScript 이벤트를 다시 바인딩해야 했습니다. React의 컴포넌트 시스템이 얼마나 편리한지 체감했습니다.

    2. 상태 변화 추적의 복잡성
    하나의 상태 변경이 여러 UI 요소에 영향을 줄 때, 모든 연관된 DOM 요소를 수동으로 업데이트해야 했습니다. React의 상태 기반 렌더링의 가치를 깨달았습니다.

    3. DOM 조작의 성능 이슈
    직접 DOM을 조작하다 보니 불필요한 리플로우와 리페인트가 자주 발생했습니다. 가상 DOM의 최적화 전략이 왜 필요한지 이해하게 되었습니다.

    4. 타입 안전성 부재
    JavaScript의 동적 타이핑으로 인해 런타임 에러가 자주 발생했습니다. TypeScript의 정적 타입 검사가 얼마나 중요한지 깨달았습니다.

학습성과

  • 해결한 기술적 문제들:
    • 상품 삭제 후 Swiper 슬라이더 동기화 문제
    • YouTube iframe API 초기화 에러 해결
    • CSS 박스모델을 고려한 DOM 사이즈 계산
    • 동적 타입으로 인한 id 값 타입 변환 이슈
  • 핵심 학습 성과:

    jQuery 셀렉터의 효율적 사용법과 이벤트 위임 패턴을 익혔으며, CSS3 애니메이션과 jQuery 애니메이션의 차이점을 이해하게 되었습니다. 특히 모바일 터치 이벤트 처리와 성능 최적화의 중요성을 깨달았습니다.

  • 완성도 높은 웹접근성:

    skipNavigation, ARIA 속성, 탭 인덱스 관리, 스크린 리더 지원 등을 직접 구현했습니다. 특히 모달, 아코디언, 탭 컴포넌트의 키보드 네비게이션과 접근성 속성을 완벽히 적용했습니다.

  • 프레임워크 이해도 향상:

    이 프로젝트를 통해 React Hook, 가상 DOM, TypeScript의 가치를 몸소 체감할 수 있었습니다. 단순한 라이브러리 사용법을 넘어서 왜 이런 도구들이 필요한지 근본적으로 이해하게 되었습니다.
